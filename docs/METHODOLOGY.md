# 평가 방법론

평가 설계와 그 근거를 정리한다. 같은 설정으로 실험을 그대로 다시 돌릴 수 있도록 하는 것이 목표다.

## 1. 평가 질문

1. Laya 결정 모델은 한국어·영어 입력에서 개인정보 포함 메시지를 얼마나 잡아내고(탐지율), 정상 메시지를 얼마나 막는가(오탐률)?
2. 표면 형태를 바꾼 변조 입력(전각, 폭 0 공백, 숫자를 단어로 쓰기 등)과 "개인정보 아님"이라는 조작 문구에도 판단이 유지되는가?
3. 어떤 개인정보 유형(카테고리)에 강하고 약한가? 모델이 고른 유형이 얼마나 정확한가?
4. 검토 라벨로 추가 학습하면 같은 평가용 데이터셋에서 얼마나 좋아지는가?

## 2. 판정 형식 — 질문 하나, 점수와 유형

모든 모델을 판정 질문 하나(`configs/question.yaml` 의 `pii_type`)로 평가하고 학습한다. 영어 지침의 `choice` 질문이고, 선택지는 아래 카테고리 8개(`none` 포함)다. 한국어·영어 문장 모두 같은 질문을 쓴다.

| 출력 | 정의 | 쓰임 |
|---|---|---|
| 점수 `score` | 1 − P(`none`) | 개인정보가 들어 있을 확률. 운영 기준의 임계값과 비교해 차단 |
| 유형 `choice` | 확률이 가장 높은 선택지 | 개인정보 유형 보고 (차단 판정에는 쓰지 않음) |
| `probabilities` | 선택지별 확률 | 유형별 확률. 개인정보 문장의 유형 맞힘은 `none` 을 뺀 최댓값으로 센다 |

카테고리 (가드레일 공통 분류 → 국내 법령 대응):

| 키 | 이름 | 예 | 근거 |
|---|---|---|---|
| `none` | 개인정보 없음 | 주문번호, 금액, 회사 대표번호, 마스킹 값, 필드명 | — |
| `national_id` | 고유식별정보 | 주민·외국인등록번호, 여권, 운전면허 | 개인정보보호법 제24조 |
| `financial` | 금융정보 | 계좌, 카드, CVV, IBAN, PIN | 신용정보법 |
| `credential` | 계정·인증정보 | ID, 비밀번호, API 키, IP | — |
| `sensitive` | 민감정보 | 건강, 신체, 혈액형, 종교 | 개인정보보호법 제23조 |
| `contact` | 연락처 | 개인 전화, 이메일, 주소 | — |
| `identity` | 인적사항 | 이름, 생년월일, 나이, 성별 | — |
| `quasi_identifier` | 준식별자 | 직장, 학교, 직책, 차량번호 | 결합 시 식별 가능 |

한 메시지에 여러 유형이 있으면 대표 카테고리는 더 민감한 쪽(`taxonomy.PRIORITY` 순서)으로 정한다.

### 판단 기준 (질문 지침에 명시)

- **개인정보 아님**: 필드·컬럼·변수·함수 이름, 형식 설명·정규식, 플레이스홀더, 마스킹 값, 널리 알려진 예시·더미 값(홍길동, 010-1234-5678, 4111-1111-1111-1111, test@example.com, 127.0.0.1 등 사설 IP), 회사·시스템 정보
- **개인정보 맞음**: 실제처럼 보이는 값은 문서·로그·설정·소스코드 안에 있어도 개인정보

입력 형태(대화, 문서, 로그, 설정, 소스코드)와 상관없이 같은 기준을 쓴다. 기술 텍스트 사례는 합성 데이터셋에 포함되어 있다.

## 3. 데이터셋

`make prepare` 가 만드는 기본 데이터셋이다. 직접 만든 데이터셋을 같은 형식으로 추가할 수 있다([DATASETS.md](DATASETS.md)).

| 데이터셋 | 언어 | 구성 | 출처 · 라이선스 | 용도 |
|---|---|---|---|---|
| `kdpii_ko` | ko | 대화 단편 53,778 (PII 19,037) | KDPII DATASET REVISED (Zenodo 원본, doi:10.5281/zenodo.16759166), CC BY 4.0 | 주 한국어 벤치마크 |
| `synth_fin_ko` | ko | 금융 CS 문장 + hard negative + 기술 텍스트 | 자체 생성 (seed 0) | 도메인 탐지율·오탐률 |
| `synth_fin_en` | en | 같은 구성의 영어판 | 자체 생성 | 영어 탐지율·오탐률 |
| `gretel_fin_ko` (선택) | ko | 금융 문서 KO 번역 (PII만) | gretelai 원본 Apache-2.0, 번역본 라이선스 미명시 → `--with-gretel-ko` 일 때만 | 긴 문서 탐지율 |
| `gretel_fin_en` | en | 금융 문서 English test (PII만) | gretelai, Apache-2.0 | 긴 문서 탐지율 |
| `evasion_ko/en` | ko/en | 합성셋 변조본 | 자체 생성 | 변조 강건성 |

- 원본은 Zenodo 레코드(md5 검증)와 Hugging Face 커밋 SHA로 고정한다(`src/piiguard_laya/data/prepare.py: SOURCES`). 라이선스와 출처 표기는 [THIRD_PARTY.md](THIRD_PARTY.md) 참고. 원본 파일의 sha256 은 각 데이터셋의 `dataset.json` 에 남는다.
- 같은 문장이 여러 번 나오면 첫 행만 남긴다(값 칸이 없는 합성 템플릿, "네, 감사합니다." 같은 짧은 대화 응답). 같은 문장이 calib · test · train 에 동시에 들어가지 않는다.
- **hard negative**는 개인정보처럼 보이지만 아닌 문장이다: 주문·거래·승인번호, 금액, 날짜, 회사 대표번호, Luhn 이 틀린 16자리, 날짜가 불가능한 주민번호 형태, 마스킹 값, 회사 공용 메일, 값 없이 개인정보 *주제*만 묻는 질문, 필드명·스키마·더미 값만 있는 코드.
- 합성 PII 값은 무작위이며, 체크섬이 있는 형식은 검증을 통과하게 만들었다.
- Gretel 데이터에서 `company`/`date`/`time` 라벨만 있는 문서는 개인정보 양성에서 뺐다.

### 분할 (누수 방지)

`sha256(id)` 로 결정적으로 나눈다. 합성 데이터는 **템플릿 단위**로 나눠 학습과 평가에 같은 문장 틀이 들어가지 않는다. 변조본은 원문의 분할을 따른다.

| 분할 | 비율 | 저장 위치 | 용도 |
|---|---|---|---|
| `calib` | 20% | `datasets/<이름>/` | 임계값(운영 기준) 결정. 성능 지표에 넣지 않음 |
| `test` | 30% | `datasets/<이름>/` | **보고용 수치는 여기서만** |
| `train` | 50% | `training/seed/` (표본) | 학습 전용. 데이터셋마다 최대 1,500건 (정상 문장을 절반까지 먼저, 나머지는 개인정보 문장) |

`make train` 은 평가용 데이터셋과 원문이 같은 학습 행을 자동으로 뺀다.

## 4. 운영 기준 (test 를 보지 않는다)

임계값은 모델마다 한 번, 모든 평가용 데이터셋의 calib 행을 합쳐서 정한다(데이터셋마다 최대 2,000건, `configs/bench.yaml: calibration`). 결과는 `reports/<모델 id>/calibration.json` 에 남고, 그 모델의 모든 데이터셋에 같은 값을 쓴다. 임계값은 calib 에서 정한 뒤 test 에 고정 적용한다.

| 운영 기준 | 정의 |
|---|---|
| `recall95` 누락 최소화 | calib 개인정보 문장 탐지율 ≥ 95% 가 되는 가장 높은 임계값 |
| `fpr05` 오탐 최소화 | calib 정상 문장 오탐률 ≤ 5% 가 되는 가장 낮은 임계값 |
| `default` 기본 기준 | 0.5 고정 |

`configs/bench.yaml` 의 `operating_points` 에서 기준을 더할 수 있다(`target_fpr`, `target_recall`, `fixed`, `max_f1`).

calib 과 test 의 분포가 조금만 달라도 test 오탐률은 목표(5%)에서 벗어날 수 있다. 이 차이는 그대로 보고한다. 정상 문장의 점수가 1.0 근처에 몰려 있으면 목표 오탐률을 맞출 임계값이 1 을 넘는다. 이때 그 기준에서는 아무것도 차단하지 않으며, 결과 페이지에 "1 초과 (차단 없음)"으로 표시된다.

## 5. 지표

양성 = 개인정보 포함, 차단 = 양성 판정.

| 지표 | 정의 | 의미 |
|---|---|---|
| 정확도 accuracy | (TP+TN)/N | 전체 판정 일치율 |
| 탐지율 recall (TPR) | TP/(TP+FN) | 개인정보 메시지 중 차단 비율 |
| 미탐률 FNR | FN/(TP+FN) | 개인정보가 통과한 비율 (= 1 − 탐지율) |
| 오탐률 FPR | FP/(FP+TN) | 정상 메시지 중 차단 비율 |
| 정밀도 precision | TP/(TP+FP) | 차단 중 실제 개인정보 비율 |
| F1 / F2 | 조화평균 / 탐지율 가중 | 미탐 비용이 크면 F2 를 함께 본다 |
| AUROC / AUPRC | 순위 성능 | 임계값과 무관한 분리 능력 |
| Brier / ECE | 확률 보정 | 확률값을 그대로 믿을 수 있는지 |

- 비율의 95% 신뢰구간은 Wilson 방식이다.
- 지표는 직접 구현했고 `tests/test_core.py` 에서 손계산·sklearn 정의값과 맞춰 검증한다.
- 전체 통합 지표는 정상 문장이 있는 데이터셋만 합친다. 개인정보 문장만 있는 Gretel 데이터셋은 탐지율만 의미가 있다.
- 두 모델 비교(`make compare`)는 같은 test 문장에 대한 exact McNemar 검정을 함께 보고한다.

## 6. 재현성과 기록

- `reports/<모델 id>/model.json`: 모델 종류(Base · 학습된 모델) · 위치, Base 모델은 받은 저장소 · 커밋, 학습된 모델은 모델 카드 요약, 장치, 판정 질문 버전 · sha256, 호스트
- `reports/<모델 id>/<데이터셋>/meta.json`: 평가 시각, 데이터셋 sha256, 표본 수(`LIMIT`)
- `reports/<모델 id>/<데이터셋>/predictions.jsonl`: 문장별 원문, 정답, 점수, 모델이 고른 유형과 유형별 확률. 원문이 들어 있으므로 실제 서비스 데이터로 평가했다면 접근 권한을 관리한다.
- 지표는 저장된 점수와 `calibration.json` 만으로 다시 계산한다. `make site` 는 모델을 돌리지 않고 결과 페이지를 다시 만든다.
- Base 모델은 `models/base/<이름>/MODEL_CARD.json` 에 받은 저장소 · 커밋 · 라이선스가 남는다. 처음 받을 때 `LAYA_REVISION=<commit>` 으로 리비전을 고정할 수 있다 (예: `convaiinnovations/laya` `e333cb7c823cd1787276228260f56d02fbf5180b`).
- 학습된 모델은 `models/trained/<이름>/MODEL_CARD.json` 에 기준 모델 · 계보 · 학습 데이터 sha256 · 설정이 남는다([TRAINING.md](TRAINING.md)).

## 7. 한계

- 합성 데이터는 실제 트래픽 분포가 아니다. 실제 서비스에 적용할 임계값은 해당 데이터의 검토 라벨로 다시 측정하는 것을 권장한다.
- KDPII 는 직장·학교 같은 준식별자까지 개인정보로 라벨링되어 있어 국내 법령 기준보다 넓다.
- 기본 체크포인트(학습 전)는 점수가 1.0 근처에 몰려 있어 임계값 해상도가 낮다. 점수는 반올림하지 않은 P(`none`) 로 계산해 소수 여섯째 자리까지 남긴다.
- GPU bf16 과 CPU fp32 는 확률이 소수 둘째 자리까지 달라질 수 있다. 임계값은 운영할 장치·정밀도로 다시 정한다(`LAYA_CUDA_AMP`).
